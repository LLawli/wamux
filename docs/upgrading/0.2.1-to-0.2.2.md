# Upgrading from 0.2.1 to 0.2.2

No `.proto` field is retyped, but the release artifacts changed, polls sent to
a channel follow WA Web, and four `RawEvent` kinds became typed. The store
needs no migration.

## Operators

- **The tarball is the static musl build (#218):**
  `wamux-<version>-x86_64-unknown-linux-musl.tar.gz` (it was the gnu build).
  Update download and checksum scripts to the new name. The GHCR image carries
  the same binary.
- **The image is built on `scratch` (#218):** no shell and no libc, so
  `docker exec ... sh` no longer works. For a Debian runtime, build
  `Dockerfile.glibc` (`docker build -f Dockerfile.glibc .`). The image creates
  `/var/cache/wamux`, the default media spool.
- **The daemon sets its own umask to `077`** for every command. systemd's
  `UMask=0077` stays as a second layer; a socket parent the daemon creates is
  still `0750`.

## Edge authors

### Polls sent to a channel (#220)

A `SendPoll` to a `@newsletter` is published by the library the way WA Web
does. Polls to chats and groups do not change.

| Change | Before | Now |
|---|---|---|
| `selectable_count` | `1..=options` | `1` (single answer) or `0` (several); above 1 is `InvalidArgument` |
| `SendPollResult.message_secret` | 32 bytes | empty: a channel poll is plaintext |
| A blank question or option | published | `InvalidArgument` |

For a channel poll with several answers, send `selectable_count = 0` (a chat
still refuses 0). Do not store or require a secret for a channel poll.
`SendNewsletterPollVote` never used it.

### RawEvent kinds that became typed (#215)

| `RawEvent.kind` | Now |
|---|---|
| `UnarchiveChatsSettingUpdate` | `AccountSettingUpdate.unarchive_chats` (the inverse of the phone's "keep chats archived") |
| `LabelSublistUpdate` | `EventEnvelope.label_sublist = 38` |
| `CallLogHistory` | `EventEnvelope.call_log_history = 39` |
| `ReachoutTimelockUpdate` | `EventEnvelope.reachout_timelock = 40` (still followed by a `MexNotification`) |

Fields the library keeps optional cross as `optional`: check presence.

### Other changes

- **A malformed `quote.quoted.chat` on a send is `InvalidArgument` (#217).** The
  field used to be ignored. When it names another chat, the send is a private
  reply or a reply to a status.
- **`QuoteContext.quoted.chat` on an inbound quote names the quoted message's
  chat (#217)**, which can differ from the reply's (a private reply to a group,
  a reply to a status). It was always the reply's own chat. Quotes and mentions
  are also read from media replies now.
- **`monotonic_seq` is strictly increasing per account (#213)**, in dispatch
  order, and starts again at 0 when the daemon restarts.
- **A chat-lock mutation without a `locked` value** is no longer reported as an
  unlock.
