# Upgrading from 0.2.3 to 0.2.4

No `.proto` field changes. whatsapp-rust moved to `66eb7331`, and pairing and
logout answer differently. The store needs no migration, and 0.2.3 still opens
a store 0.2.4 wrote.

## Operators

- **New: `blocking_shutdown_timeout_ms`** (env
  `WAMUX_BLOCKING_SHUTDOWN_TIMEOUT_MS`, default 5000). With the defaults the
  worst case after SIGTERM is 18 s, well under systemd's 90 s.
- **WhatsApp error text in the logs is redacted** by the library
  (`other(len=N)` instead of the server's text). Adjust log alerts that matched
  that text.

## Edge authors

- **`PairWithQr` and `PairWithCode` refuse an account that holds a paired
  identity (#253)** with `FailedPrecondition`, at once, including a logged-out
  account: `Logout` keeps the identity, and WhatsApp answers its next connect
  with 401, so it never gets a QR. To pair again, call `DeleteAccount` and
  `CreateAccount` (a new uuid).
- **A pairing call fails when the connect fails (#250)**, with the `Status`
  `ConnectAccount` gives (`ResourceExhausted` for a full budget,
  `Unavailable`), instead of staying open.
- **A pairing stream can end with no terminal update (#247)**: that means the
  daemon is stopping.
- **`GetAccountStatus` reads `LOGGED_OUT` as soon as `Logout` returns (#257)**,
  so the status can lead the matching `ConnectionStateChanged`.
- **Device lists are verified against their ADV signature.** A companion the
  library cannot verify is left out of a group send, a DM to a list without the
  signature fails, and a message from such a companion arrives as undecryptable
  (the library asks the sender to resend).
- **A group action this build does not know** arrives as `GroupUnknownAction`
  with its wire tag.
- New, additive: `SendText`, `SendMedia` and `SendContact` take
  `quoted_message` (#230), so receivers without the original still show the
  quote.
